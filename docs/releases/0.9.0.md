# Axoloty 0.9.0 release notes

Axoloty 0.9.0 moves the toolchain to Swift 6.4, completes the split of
concrete firmware into `phynics/axoloty-embedded`, and adds an experimental
Zenoh transport. It remains a pre-1.0 release. The full list of changes is in
[`CHANGELOG.md`](../../CHANGELOG.md).

## Swift 6.4 is required

Every package manifest declares Swift tools version 6.4, so consumers need a
Swift 6.4 toolchain to resolve and build Axoloty 0.9.0. The library adopts
`Span` for borrowed byte access, typed throws on new and changed signatures,
and asynchronous cleanup that still runs when the caller is cancelled
([epic #878](https://github.com/phynics/axoloty/issues/878)). There is no
other source-breaking change to the library API.

## The embedded split is complete

Concrete firmware, board integration, and device qualification now live in
[`phynics/axoloty-embedded`](https://github.com/phynics/axoloty-embedded)
([epic #845](https://github.com/phynics/axoloty/issues/845)). This repository
keeps the portable wire, object model, protocol, Coaty models, and static
runtime, and its required CI still proves they compile for Embedded Swift
without a firmware checkout. Firmware consumes an exact Core revision through
the [embedded consumer contract](../embedded-consumer-contract.md). In 0.9 the
contract also reports the Zenoh core artifacts.

Firmware profiles are qualified per Core release in `phynics/axoloty-embedded`,
not here.

## Experimental Zenoh transport

`Packages/AxolotyZenoh` provides `AxolotyZenoh`, a host
`AxolotyRuntimeTransport` over the pinned `zenoh-c` 1.10.0 archive, and
`AxolotyZenohCore`, an Embedded-Swift core over an Axoloty-owned C façade
([epic #796](https://github.com/phynics/axoloty/issues/796)). Coaty routes
become Zenoh key expressions unchanged, and the protocol traces match MQTT for
the closed profile. Client mode connects through `zenohd`. Peer mode connects
host runtimes without a router. Linux x86_64 and macOS arm64 are the supported
hosts. See [`docs/transports/zenoh.md`](../transports/zenoh.md).

The transport is experimental for two reasons:

- The adapter is a separate SwiftPM package that depends on the root package
  by path ([ADR 0007](../adr/0007-zenoh-adapter-package-boundary.md)), so it
  is consumed from a checkout of this repository, not through a URL
  dependency.
- Its wire encoding may move to the `axoloty/1` CBOR extension profile
  ([ADR 0008](../adr/0008-axoloty-1-cbor-extension-profile.md)). The
  `coaty/3` JSON profile on MQTT is unchanged.

MQTT remains the default and validated transport.

## Developer tooling

`axoloty-tool` loses three commands: `measure timing`, `test offline` (use
`check`), and `test integration`, which had only reported a retired tier.
Ordinary `make verify` no longer builds every public product in both debug and
release configurations. `make checkpoint` still does. Thirteen canonical
test nodes that checked deleted files or retired symbols are gone, and the
module policy enforces the import boundaries they covered.

## Known limitations

- Device performance budgets in
  [`docs/performance-budgets.md`](../performance-budgets.md) still come from
  the C surrogate and do not match production Embedded Swift measurements
  ([#987](https://github.com/phynics/axoloty/issues/987)).
- macOS and iOS are declared platforms without automated CI.
