# Axoloty 0.8.2 release notes

Axoloty 0.8.2 is a tooling fix release with no public API change. It is the
revision `phynics/axoloty-embedded` locks against, tracked by
[epic #845](https://github.com/phynics/axoloty/issues/845). It remains a
pre-1.0 release.

Consumers who do not run `axoloty-tool` from a working directory under `/tmp`
on macOS need no changes.

## Preparation works from a `/tmp` working directory

`axoloty-tool embedded consumer prepare` failed whenever the caller's working
directory was under `/tmp` on macOS, and blamed the selected checkout:

```
error: AXOLOTY_SOURCE_DIR must be the canonical Git checkout root
```

The checkout was fine. The git subprocess never ran. The artifact root is
`<working directory>/.testing/runs`, and Foundation's filesystem-resolving
normalizations rewrite an existing `/private/tmp` path to `/tmp`, which is a
symbolic link, so root validation refused a root the caller never named that
way. `getcwd` had already returned the real, symlink-free path.

The same rewrite made containment inconsistent. It applies to a path that
exists but not to one that does not, so an existing root normalized to
`/tmp/...` while its not-yet-created child kept `/private/tmp/...`, and the
child looked like it escaped its own root.

Artifact paths are now normalized lexically: merged with the working directory
with `.` and `..` resolved, without consulting the filesystem. The
per-component symbolic-link rejection remains the safety mechanism, so an
artifact root that genuinely is a symbolic link is still refused.

`embedded consumer prepare` also reports what actually failed when git cannot
start, rather than making a claim about the selected checkout.

## Known limitation

An artifact root whose *ancestor* is a symbolic link is still rejected. On
macOS that includes anything under `/var/folders`, which is where
`FileManager.temporaryDirectory` points. Accepting it would mean resolving
ancestors and trusting the caller's chosen root, which changes a deliberate
safety rule. [Issue #885](https://github.com/phynics/axoloty/issues/885)
records the decision.

## Validation

Required CI passed on [#886](https://github.com/phynics/axoloty/pull/886).

On macOS 26 with Swift 6.4: the new regression test
`artifactStoreAcceptsARootUnderPrivateTmp` fails on the unfixed code and
passes with the fix; `embedded consumer prepare` completes from a
`/private/tmp` working directory with its command artifacts recorded, and from
an unrelated root as before; `repository validate` and
`repository validate --embedded-consumer-contract` pass. The full `Tools`
suite was compared against `main` on that host with no new failures.

No portable production source changed, so the riscv32 Embedded consumer gate,
the firmware build, and device evidence are unchanged from 0.8.0.
