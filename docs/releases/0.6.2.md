# Axoloty 0.6.2 release notes

Axoloty 0.6.2 is a wire-topic capacity hotfix for application routes that
contain several UUIDs. It remains a pre-1.0 release.

## Changed

- The host and Embedded Swift profiles accept MQTT topics up to 256 bytes and
  reject topics of 257 bytes.
- Runtime namespaces may contain up to 64 UTF-8 bytes. The largest generated
  filtered Coaty Core 3 topic occupies 243 bytes.
- The static runtime retains routes in one deduplicating 2 KiB arena. Fan-out
  actions that use the same route share its stored bytes.
- External-IO route metadata accepts bounded MQTT topic names and rejects
  wildcard, control, quote, backslash, NUL, and invalid-level forms.

The 2,048-byte payload ceiling from 0.6.1 remains unchanged. MQTT and Coaty do
not define Axoloty's 256-byte topic or 2 KiB payload limits. Axoloty applies
these limits so host and embedded profiles use the same finite storage.

## Validation

The ordinary verification suite and focused topic-boundary tests pass. Live
external-IO flows pass in both Axoloty-to-CoatyJS and CoatyJS-to-Axoloty
directions. A production Embedded Swift run on ESP32-C6 passed all 315 records,
including the 256/257-byte topic and 2,048/2,049-byte payload boundaries.

## Installation

```swift
.package(url: "https://github.com/phynics/axoloty", from: "0.6.2")
```
