# Axoloty 0.7.0 release notes

Axoloty 0.7.0 is the source-breaking architecture-stabilization release
tracked by [epic #753](https://github.com/phynics/axoloty/issues/753). It
remains a pre-1.0 release.

## Highlights

- `RuntimeBuilder` owns a finite transactional registration draft and
  `RuntimeDefinition` is the immutable value its `finish()` produces.
  Registration failures are atomic: a failed draft discards every handler,
  stream, and module reservation it created.
- First-party runtime modules register under stable internal keys, and
  duplicate registration is rejected rather than silently accepted.
- SensorThings gains Thing-driven observation. The bounded registry performs
  exact Thing discovery and a parent-filtered Sensor query, and returns
  catalogue-change and relationship-checked observation streams.
- Typed IO state is concentrated behind the executor that owns it, rather
  than spread across the runtime surface.
- The canonical test taxonomy is four categories — `ci`, `wire`, `embedded`,
  and `release` — replacing eleven tiers and nine named plans. A category
  declares whether it is executed or attested from recorded evidence.

## Breaking API change

`RuntimeDefinition` is no longer mutable and no longer seals itself.
`SealedRuntimeDefinition`, `RuntimeDefinition.Builder`, `seal()`, and the
mutable registration methods are removed, as are the standalone SensorThings
source and observer configuration types. The component SPI is renamed to a
module SPI throughout.

Every removed public symbol and its replacement is listed in the
[0.6-to-0.7 migration guide](../migration/from-0.6-to-0.7.md). The 0.7
package is not API-stable.

## Repository layout

`Tests/Support` is grouped into `checks/`, `selftests/`, `embedded/`,
`benchmarks/`, `evidence/`, `wire/`, and `lib/` instead of one directory of
127 files. `Tools/AxolotyTooling` and its tests are grouped by command
family, and the host runtime's executor, IO, and transport sources sit in
subdirectories of `Source/Runtime`. No module names changed, so consumer
`import` statements are unaffected.

`AxolotyVersion.current` now resolves the checkout version by searching
upward from its own source file. It previously expanded `#filePath` in the
*caller's* file and walked up a fixed three directories, so moving any
calling file silently degraded the reported version to `"unavailable"`.

## Validation

Static gates, harness self-tests, and the repository authority pass on the
release tree. The canonical `ci` and `wire` categories run in CI.

The `embedded` category and `make checkpoint` require a Linux host with an
attached ESP32-C6 and are not covered by this document; the release is not
complete until those are recorded.
