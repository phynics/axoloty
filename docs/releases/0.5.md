# Axoloty 0.5.0 release notes

> **Axoloty 0.5 is a development checkpoint. APIs and module boundaries may
> continue to change before 1.0.**

## Overview

Axoloty 0.5.0 strengthens protocol conformance, bounded embedded routing,
runtime recovery, and release validation after the 0.4.0 checkpoint.

This release is **not API-stable**.

## Highlights

- Exact Coaty topic and event-code layouts are enforced with regression and
  live compatibility coverage.
- Embedded routing handles reassociation and external IoValue delivery
  deterministically, with bounded tables and explicit capacity errors.
- MQTT restart, ingress backpressure, publication diagnostics, and host model
  validation are more robust under failure and overload.
- Release tooling separates committed offline fixtures from fresh wire
  evidence, isolates scratch builds, and records timing and checkpoint data.

## Breaking changes

No additional intentional source-breaking change is introduced by this
checkpoint beyond the 0.4.0 throwing wire initializers. Existing users should
continue to add `try` when constructing owned wire values and calling
`BorrowedWireEvent.owned()`.

## Compatibility and migration

The Coaty wire shape is now checked more strictly. Applications using the
documented topic layouts remain compatible; custom producers should verify
their topic prefixes and event codes against
`docs/wire-compatibility.md`.

## Validation boundary

The release gates use the canonical Linux container, including ordinary
verification, checkpoint validation, fixture-bundle validation, and the clean
external SwiftPM consumer. Offline fixture bundles explicitly declare
`evidence.live: false`; they are not substitutes for a live wire capture.
Physical ESP32-C6 checks are opt-in and were not run. macOS and iOS remain
supported but are not covered by dedicated CI runners.
