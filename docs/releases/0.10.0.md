# Axoloty 0.10.0 release notes

Axoloty 0.10.0 adds the `axoloty/1` CBOR wire profile, makes it the only Zenoh
encoding, and audits and freezes the candidate Core 1.0 surface. It also moves
the runtime and debug products to `phynics/axoloty-debug`. It remains a
pre-1.0 release. The full list of changes is in
[`CHANGELOG.md`](../../CHANGELOG.md).

Firmware in [`phynics/axoloty-embedded`](https://github.com/phynics/axoloty-embedded)
can select the `v0.10.0` tag after publication through the
[embedded consumer contract](../embedded-consumer-contract.md).

## `axoloty/1` CBOR

The `axoloty/1` profile carries the Coaty Core Profile 3 event families and
object semantics unchanged over a deterministic CBOR payload (RFC 8949
§4.2.1). It uses the route prefix `axoloty/1`, so a receiver selects the profile
from the route and never from a content-type hint. The reader rejects
indefinite lengths, non-minimal integers, duplicate map keys, and excessive
nesting. The bounds are 256-byte routes, 2,048-byte payloads, and 32 levels of
nesting. See [`docs/protocol/axoloty-1.md`](../protocol/axoloty-1.md).

`coaty/3` is unchanged. Its field presence and wire bytes are identical to
0.9.0. The `wire-cbor` tier replays a frozen `coaty/3`/`axoloty/1` golden
corpus and the host/static trace-parity replay.

## Zenoh carries only `axoloty/1`

Zenoh carries only the `axoloty/1` CBOR profile
([ADR 0009](../adr/0009-zenoh-carries-only-axoloty-1.md)). The binding admits
every sample by its validated route. A non-CBOR encoding label is advisory and
reported once as a diagnostic. MQTT keeps the sealed `coaty/3` JSON profile.

**Migration: 0.9.x Zenoh peers do not interoperate.** A 0.9.x Zenoh peer
carried the `coaty/3` JSON routes. A 0.10.0 Zenoh peer carries only
`axoloty/1` CBOR. There is no runtime negotiation or dual mode. Upgrade both
peers. MQTT peers are unaffected.

The Zenoh package stays experimental and outside the six root products. Host
qualification covers queue saturation, oversized-sample rejection, router
restart recovery without replaying a correlated request, and external
consumption, on Linux x86_64 only. See
[`docs/transports/zenoh.md`](../transports/zenoh.md).

## Candidate Core 1.0 surface

The audit freezes `Axoloty`, `AxolotyWire`, `AxolotyProtocol`,
`AxolotyObjectModel`, `AxolotyStaticRuntime`, and `AxolotyMQTT`
([ADR 0012](../adr/0012-approved-product-and-ownership-contracts.md)). The
reviewed public-symbol baseline is
[`docs/api/core-1.0-public-symbols.json`](../api/core-1.0-public-symbols.json),
checked by `make api-baseline`. The audit changed some public declarations; see
[`docs/migration/pre-1.0-to-1.0.md`](../migration/pre-1.0-to-1.0.md). Because
0.10.0 is pre-1.0, the API may still change before the 1.0 release.

## Runtime observations

`RuntimeDiagnostics` events carry a monotonic sequence, a runtime timestamp,
and an optional typed observation for reconnects, admission and saturation,
request outcomes, observable presence, transport failures, and capabilities.
A reconnect replays only one-way publications; an accepted request whose send
failed is dropped.

## Embedded consumers

[`docs/embedded-consumer-contract.json`](../embedded-consumer-contract.json)
declares both wire profiles. `axoloty1CBOR` is mandatory and does not require
`_JSONCore`; `coaty3JSON` requires it. Select the CBOR-only graph with
`embedded consumer prepare --profile axoloty1CBOR`. Preparation omits the JSON
parser from the selected source and dependency report. The RISC-V gate compiles
and partially links all five portable modules without `_JSONCore`. It does not
execute the Core fixture. Only the separate Wire probe executes on the host.

`BoundedCBORObject<byteCapacity, fieldCapacity>` owns a validated CBOR object
map and lends exact encoded field values through synchronous callbacks. It
preserves unknown fields without converting them to JSON. Its field capacity
also depends on the shared reader's 24-field index limit.

JSON-only object decoding and filtering APIs do not gain CBOR equivalents in
this release. Some JSON-specific calls trap without `_JSONCore`; consumers
must use the documented CBOR entry points. Expanded operation round trips and
these API restrictions are tracked in
[#1057](https://github.com/phynics/axoloty/issues/1057). Firmware profiles are
qualified per Core release in `phynics/axoloty-embedded`, not here.

## Debug products and tooling

`axoloty-inspect`, `axoloty-mcp`, and the `serve mqtt|mcp|dev` command now
live in [`phynics/axoloty-debug`](https://github.com/phynics/axoloty-debug).
The `Tools` harness in this repository is library-free. The canonical check
runner schedules independent nodes concurrently; set
`AXOLOTY_CHECK_CONCURRENCY=1` for serial runs.

## Known limitations

- macOS is best effort and iOS is experimental and unvalidated. Linux is the
  validated host.
- The Zenoh results cover Linux x86_64 host topologies. They include no
  device, macOS, or iOS qualification.
- The `ProtocolTraceRuntimeReplay` seed helper is test support.
