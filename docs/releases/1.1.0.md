# Axoloty 1.1.0 release notes

Axoloty 1.1.0 is a minor release of the frozen Core products. It adds opt-in
soft-state presence on `axoloty/1` and the public host and static APIs that
drive it. `coaty/3` bytes and field presence are unchanged. The full list of
changes is in [`CHANGELOG.md`](../../CHANGELOG.md).

## Soft-state presence

Zenoh has no broker last will. A peer that loses power or crashes therefore
sends no Deadvertise, and a late joiner never sees an object advertised before
it connected. Soft-state presence closes that gap on `axoloty/1`: an owner
refreshes a leased object, and a peer removes it when the lease runs out.

Presence is opt-in. Disabled presence keeps the pre-1.1 behavior and emits no
lease fields. Enable it with `RuntimePresenceConfiguration`:

```swift
let presence = try RuntimePresenceConfiguration(leaseMS: 45_000)
let definition = try RuntimeBuilder(
    identity: identity,
    namespace: "example",
    presence: presence
).finish()
```

The configured lease applies to the runtime identity and every registered
typed IO endpoint. Application objects declare their own lease through:

```swift
await runtime.advertise(objectID: id, object: cborObject, leaseMS: 10_000)
```

`AxolotyRuntime.presenceExpiries()` reports peer removals through a bounded
additive stream. A peer that declares no lease never expires.

## Wire

`axoloty/1` Advertise gains two optional fields:

- `leaseMs` in `1_000...3_600_000`;
- `ownerEpoch` in `1...2_147_483_647`.

Both are present together or absent together. They are encoded only in CBOR;
the sealed `coaty/3` JSON profile never carries them. An older `axoloty/1`
receiver ignores the two fields, as it already ignores unknown envelope fields.
This is a backward-compatible extension under [`docs/versioning.md`](../versioning.md),
not a new profile or `axoloty/2`.

A same-epoch refresh renews silently and delivers nothing. A changed epoch
re-announces the object, which releases the Associate rows that name it. A
silent lease expiry keeps those rows until the owner's Deadvertise, a
changed-epoch re-announce, or a transport reset. Code that relies on Associate
rows must account for that window.

## Behavior to know

- The default host lease is 45 seconds, refreshed every `max(50, 2L/9)`
  milliseconds. Three consecutive lost refreshes stay inside the lease; the
  fourth may expire the object.
- Expiry is advisory. Expiry reports and Advertise deliveries travel on
  separate streams, so a consumer can observe a healing Advertise before the
  expiry report that preceded it. A false expiry heals at the next refresh.
- The host refresh phase is deterministic per object and survives a reconnect.
  The identity and typed IO endpoints re-announce immediately on recovery;
  application objects wait for their unchanged phase.
- Graceful stop Deadvertises application objects, then typed IO endpoints, then
  the identity. A transport failure ends that sequence at the first error on
  every profile.
- A raw Advertise carrying `leaseMs` or `ownerEpoch` is rejected while
  presence is enabled, so no leased entry exists without a refresher.
- Enabling presence on a `coaty/3` transport fails `start()` with
  `AxolotyError.invalidConfiguration(option: "presence", ...)` before the
  transport opens.

## Shipped `axoloty/1` receivers

A receiver built before 1.1 rejects a refreshed lease as `duplicate` until it
is updated, because pre-1.1 `axoloty/1` rejects a repeated Advertise. The
object is not lost while the older receiver holds it, but it does not renew and
never expires there. Upgrade receivers before enabling presence on owners.

## Verification

- `AxolotyRuntimePresenceTests`: 23 host tests.
- Processor and static presence tests, including expiry, suspend/resume,
  re-announce, and slot reuse.
- CBOR-only `advertise-lease` and `advertise-refresh` goldens with an
  independent `cbor-x` decode and re-encode.
- `PresenceTraceParityTests`: host and static state, deliveries, expiry
  reports, and rejections match for announce, renewal, expiry, late refresh,
  Deadvertise, resurrection, and a malformed leased frame.
- Live pinned-`zenohd` test: an owner session closes with no Deadvertise and
  the observer expires the lease within the declared interval.
- `make test-tier TIER=wire-cbor`, `make test-tier TIER=zenoh-live`, and
  `make verify` pass on the release tree.

## Compatibility and support

The Core 1.0 public-symbol baseline only grows. Both original Core 1.0
`RuntimeBuilder` initializers are unchanged. A consumer that does not enable
presence needs no source change and sees no new wire fields.

Support levels do not widen. Zenoh and the device path remain experimental.
The device profiles are certified at
[`1.0.1-embedded.1`](https://github.com/phynics/axoloty-embedded/releases/tag/v1.0.1-embedded.1)
on Core v1.0.1. Core 1.1.0 is not device-qualified; the ESP32-C6 refresh loop,
power-loss expiry, `DROP` loss, queue drops, and memory budgets are tracked in
[`phynics/axoloty-embedded#156`](https://github.com/phynics/axoloty-embedded/issues/156).
