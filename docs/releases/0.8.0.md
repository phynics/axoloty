# Axoloty 0.8.0 release notes

Axoloty 0.8.0 is a source-breaking release. It is the exact Core revision the
embedded firmware split in
[epic #845](https://github.com/phynics/axoloty/issues/845) locks against. It
remains a pre-1.0 release.

## Highlights

- Firmware can consume the portable Core from outside this repository through
  a small, versioned [embedded consumer contract](../embedded-consumer-contract.md).
- Required CI proves Embedded Swift portability without firmware, ESP-IDF, a
  broker, or hardware.
- Transport failures reach the runtime as an owned, typed value.
- The host runtime installs its identity deadvertisement as an MQTT last will.
- Static-runtime construction reports invalid capacities as typed errors
  instead of trapping, and a failed action batch leaves no partial state.

## Breaking API changes

- `AxolotyRuntimeTransport.setFailureHandler(_:)` takes a
  `(RuntimeTransportFailure) -> Void` handler.
- `StaticRuntimeDefinition.init` and `StaticRuntime.init` throw
  `ProtocolCapacityError`.
- `WireBufferConfig.maxSubscribers`, `maxFamilyEntries`, and
  `maxFamilySubscribers` are removed.

Each change and its replacement is described in the
[0.7-to-0.8 migration guide](../migration/from-0.7-to-0.8.md). Consumers of
`AxolotyRuntime` with the bundled `AxolotyMQTT` transport need no source
changes.

## Embedded consumer contract

`docs/embedded-consumer-contract.json` names exactly five portable packages:
`AxolotyWire`, `AxolotyObjectModel`, `AxolotyProtocol`, `AxolotyCoatyModels`,
and `AxolotyStaticRuntime`. It records their required compiler flags, the
`StaticIoActor` macro plugin inputs, and the pinned `swift-json` identity. It
exposes no test-tree path, root `.build` path, or parent-directory layout, and
scratch space belongs to the caller.

`AXOLOTY_SOURCE_DIR` is the only local override that selects a Core checkout.
Build diagnostics report the selected commit and its dirty state. A downstream
lock, not the contract, selects the exact Axoloty revision.

`make check-embedded-core-consumer` is a required CI gate. It compiles the
portable packages for riscv32 Embedded Swift in dependency order, expands the
production macro, compiles an external consumer fixture, and partially links
the result. The contract's package set is cross-checked against
`docs/module-policy.yml`. Firmware-mediated build, link, and evidence nodes
are no longer required CI nodes; the explicit release commands still run
them until firmware moves to `phynics/axoloty-embedded`.

## Runtime behavior

- `AxolotyRuntime.run()` wakes from an executor-owned termination signal
  instead of polling, and handles cancellation during startup and shutdown.
- `state()` reports a normally closed runtime as `.stopped`. `.failed` means
  an actual failure.
- MQTT profile subscription install and removal failures surface as
  `AxolotyError.network` and clear the failed subscription state.
- `StaticRuntimeDefinition` accepts optional `maximumObjects` and
  `maximumPendingCorrelations` limits and forwards them to the protocol
  processor.

## Validation

The source tree of this release is the owner-accepted GO proof revision
`357fa3eb3b2f51d193b55833d5e5b08fb23876ba` plus version and documentation
updates. At that revision, a firmware project at an unrelated filesystem root
built and flashed ESP32-C6 firmware through the supported consumer
preparation contract, without the Core `Tests/Support` tree and without
copying portable source. The flashed artifact matched its recorded SHA-256 and
the `embedded-swift-smoke-v2` run passed all 312 deterministic cases. The
proof is recorded on
[issue #846](https://github.com/phynics/axoloty/issues/846#issuecomment-5678021364).
Required CI passed on that revision.

The optional release-lane consumer checks (`checkpoint-semver-consumer`,
`release-semver-consumer`) need the `v0.8.0` tag to be resolvable from the
repository URL, so they are verified after tagging.
