# Axoloty 0.6.1 release notes

Axoloty 0.6.1 is a wire-capacity hotfix for application objects that do not fit
within the former 512-byte payload limit. It remains a pre-1.0 release.

## Changed

- The host and Embedded Swift profiles accept wire payloads up to 2,048 bytes.
- The static runtime retains action payloads in one bounded arena. It does not
  reserve a separate 2 KiB payload buffer for every action slot.
- The compatibility documentation now identifies the 2 KiB ceiling as an
  intentional divergence from Coaty. Coaty does not define this payload limit.

Axoloty rejects inbound payloads above 2,048 bytes before parsing or protocol
state changes. It rejects oversized outbound payloads before publication.
Axoloty does not fragment or reassemble oversized Coaty messages.

## Validation

The ordinary verification suite and focused payload-boundary tests pass. A
production Embedded Swift run on ESP32-C6 passed all 314 records with zero
hot-path allocations. The run accepted a 2,048-byte payload and rejected a
2,049-byte payload.

## Installation

```swift
.package(url: "https://github.com/phynics/axoloty", from: "0.6.1")
```
