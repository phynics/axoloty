# Axoloty 0.2.0 release notes

> **Axoloty 0.2 is a development checkpoint, not a stable release.**
> Public APIs may continue to change before 1.0.

## What is Axoloty 0.2?

Axoloty 0.2.0 records the architectural progress made since the 0.1 fork
from CoatySwift. It provides a reproducible checkpoint of:

- A safe host runtime with strict Swift 6 concurrency, structured
  `AsyncStream`-based event observation, and `mqtt-nio` transport.
- A dependency-free, Foundation-free `AxolotyWire` module (131 KB stripped,
  zero host dependencies) for embedded and resource-constrained consumers.
- An ESP32-C6 Embedded Swift proof completing Advertise/Deadvertise and
  Discover/Resolve against host Axoloty and pinned CoatyJS 2.4.0 within
  explicit resource budgets (zero hot-path allocations).
- Typed Swift repository tooling (`axoloty-tool`) for check, benchmark,
  wire capture, release snapshots, and hardware gates.
- Accurate documentation of what works, what is experimental, and what
  remains unsupported.

## What's new since 0.1

### Host runtime
- Swift 6 language mode with strict concurrency.
- `AsyncStream` replaces RxSwift for all event observation.
- `mqtt-nio` replaces CocoaMQTT.
- `swift-log` replaces XCGLogger.
- `ErrorKit` with structured `AxolotyError` categories.
- Linux containerized CI with `axoloty-tool` orchestration.

### Wire module
- `AxolotyWire`: Foundation-free, zero-dependency, zero-allocation wire codec.
- `WireReader`/`WireWriter` for single-pass, borrowed-byte decode/encode.
- `BorrowedMessage`, `ByteSlice`, `TopicView` for zero-copy views.
- Semantic differential tests proving equivalence with host `Codable` path.

### Embedded (ESP32-C6)
- Static device agent with bounded Discover/Resolve lifecycle.
- On-device vector corpus: 313/313 tests pass.
- Physical interoperability: two-device exchange, host Axoloty, pinned CoatyJS
  (both directions), last-will, and broker-restart — all pass.
- Zero hot-path allocations within recorded RAM/stack/flash budgets.

### Tooling
- `axoloty-tool` Swift CLI for `check`, `hardware check`, `wire capture`,
  `release snapshots`, and `embedded verify`.
- Binary-size benchmark with 5 representative consumers.
- Live wire-capture harness for CoatyJS → Axoloty and Axoloty → CoatyJS.
- Coverage ratchet with changed-line diff reporting.

## Support levels

See [SUPPORT_MATRIX.md](SUPPORT_MATRIX.md) for the full capability matrix.

- **Validated:** Advertise/Deadvertise, Discover/Resolve, Query/Retrieve,
  Update/Complete, Call/Return, Channel, MQTT reconnect, MQTT last will,
  dynamic object-type registration, unknown/custom object decoding, Linux,
  ESP32-C6 (embedded scope).
- **Partial:** Associate/IoValue (two wire divergences), mDNS discovery
  (Apple-only, no tests).
- **Supported:** SensorThings controllers, object lifecycle, TLS (manual only),
  dynamic controller registration, macOS, iOS.

## Known limitations

- `handleAssociate` force-unwraps `isExternalRoute`, blocking JS→modern
  Associate direction.
- mDNS broker discovery is Apple-only with zero test coverage.
- TLS has no automated tests; verified only via the manual macOS oracle.
- Legacy CoatySwift ↔ Axoloty live wire compatibility is unverified
  (fixtures captured, macOS oracle runner pending).

## Not included in 0.2

- API stability guarantees (0.2 is a development checkpoint).
- WASM, SwiftUI, or SwiftData support.
- BLE, libp2p, or Constellation integration.
- RBAC or cryptographic identity.
- Transport adapter architecture.
- Full embedded event family support (only Advertise/Deadvertise and
  Discover/Resolve).
