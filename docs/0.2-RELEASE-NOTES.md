# Axoloty 0.2.0 release notes

> **Axoloty 0.2 is a development checkpoint. APIs and module boundaries may
> continue to change before 1.0.**

## Overview

Axoloty 0.2.0 records the architectural progress made since the 0.1 fork
from CoatySwift. It provides a reproducible checkpoint of a safe host
runtime, a Foundation-free wire module with a separately validated standalone
package boundary, an ESP32-C6 Embedded Swift proof,
typed repository tooling, and accurate documentation of what works and
what remains experimental.

This is **not** a v1 release and **not** API-stable.

## Major architectural changes

- **Swift 6 language mode** with strict concurrency throughout.
- **RxSwift removed** — all event observation uses `AsyncStream`.
- **CocoaMQTT replaced** by [mqtt-nio](https://github.com/swift-server-community/mqtt-nio).
- **XCGLogger replaced** by [swift-log](https://github.com/apple/swift-log).
- **ErrorKit** with structured `AxolotyError` categories.
- **CocoaPods removed** — SwiftPM-only distribution.
- **Repository renamed** from `coatyio/coaty-swift` to `phynics/axoloty`.

## AxolotyWire

- Foundation-free, zero-allocation wire codec with one direct `swift-json` /
  `IkigaJSONCore` parser dependency; the standalone package closure is
  explicitly allowlisted and excludes host runtime targets.
- `WireReader`/`WireWriter` for single-pass, borrowed-byte decode/encode.
- `BorrowedMessage`, `ByteSlice`, `TopicView` for zero-copy views.
- Semantic differential tests proving equivalence with host `Codable` path.
- 131 KB stripped binary; standalone package closure:
  `axolotywire`, `swift-json`, `swift-nio`, `swift-atomics`,
  `swift-collections`, and `swift-system`; `swift-nio` is resolution-only.

## Host runtime changes

- `@MainActor`-isolated `CommunicationManager` with structured concurrency.
- All `observe*Stream()` methods return `AsyncStream<T>`.
- `publishDiscover`/`publishQuery`/`publishUpdate`/`publishCall` return
  `AsyncStream<ResponseEventSnapshot>` instead of using completion handlers.
- `Container` bootstrap and `CommunicationManager.start()` are `async throws`.
- Five `@unchecked Sendable` declarations audited with written justification
  (all internal/private, all synchronized).

## Embedded Swift and ESP32-C6

- Static device agent with bounded Discover/Resolve lifecycle.
- On-device vector corpus: 313/313 tests pass.
- Physical interoperability evidence:
  - Two-device A↔B exchange: 10/10 both devices.
  - Host Axoloty ↔ ESP32-C6: Swift test + 10/10 device checks.
  - Pinned CoatyJS ↔ ESP32-C6 (both directions): 10/10 device checks.
  - Last-will forced reset: 8/8 device checks.
  - Broker-restart reconnect: 11/11 device checks.
- Zero hot-path allocations within recorded RAM/stack/flash budgets.

## Compatibility evidence

- **CoatyJS → Axoloty:** Validated for all event families (offline fixtures
  + live captures).
- **Axoloty → CoatyJS:** Validated for all event families.
- **Axoloty ↔ ESP32-C6:** Validated for Advertise/Deadvertise, Discover/Resolve.
- **CoatyJS ↔ ESP32-C6:** Validated for Advertise/Deadvertise, Discover/Resolve.
- **Legacy CoatySwift → Axoloty:** Compatibility-unverified (fixtures captured;
  macOS oracle runner pending).
- **MQTT lifecycle:** Four live network-failure scenarios pass (reconnect,
  broker-restart, clean-session, offline-queueing).

See [CompatibilityMatrix.md](../Tests/WireCompatibility/CompatibilityMatrix.md)
and [SUPPORT_MATRIX.md](SUPPORT_MATRIX.md) for full details.

## Tooling changes

- `axoloty-tool` Swift CLI: `check`, `hardware check`, `wire capture`,
  `release snapshots`, `release checkpoint`, `embedded verify`.
- `axoloty-inspect` CLI: passive object catalogue (`catalog`) and active
  discovery (`discover`) against a live MQTT broker, without writing a
  custom agent. NDJSON and human output modes. See
  [inspector.md](inspector.md).
- Namespace-wide `observeAdvertiseStream()` public API on
  `CommunicationManager` for inspecting all advertised objects regardless
  of type.
- Binary-size benchmark with 5 representative consumers.
- Live wire-capture harness for CoatyJS ↔ Axoloty.
- Coverage ratchet with changed-line diff reporting.
- `make checkpoint` and `make checkpoint-hardware` commands.

## Known limitations

- `handleAssociate` force-unwraps `isExternalRoute`, blocking JS→modern
  Associate direction.
- mDNS broker discovery is Apple-only with zero test coverage.
- TLS has no automated tests; verified only via the manual macOS oracle.
- Legacy CoatySwift ↔ Axoloty live wire compatibility is unverified.
- No API stability guarantees (0.2 is a development checkpoint).

## Migration notes

See [0.2-MIGRATION.md](0.2-MIGRATION.md) for migration from CoatySwift.
The guide covers: repository/package naming, Swift version requirements,
SwiftPM-only distribution, RxSwift removal, mqtt-nio transport, swift-log,
ErrorKit/AxolotyError, borrowed wire values, Linux container workflow,
and known API renames. The guide is explicitly non-exhaustive.

## Performance and resource evidence

- `AxolotyWireConsumer` stripped: 131 KB, one direct parser dependency,
  5 dynamic libs; standalone package resolution uses the tested allowlist.
- `AxolotyConsumer` stripped: 11.2 MB, 16 dependencies, 18 dynamic libs.
- All host consumers share the same dependency closure — no incremental
  benefit from subsystem splitting (decision: keep host target intact).
- ESP32-C6: zero hot-path allocations, topic parse p50 ~12µs, DTO decode
  p50 ~41µs, DTO encode p50 ~56µs.
