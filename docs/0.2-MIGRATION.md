# Migrating from legacy CoatySwift to Axoloty 0.2

> This guide is **non-exhaustive**. It covers the migration topics that are
> already understood. Additional breaking changes may exist that are not
> documented here.

## Repository and package naming

The repository moved from `coatyio/coaty-swift` to `phynics/axoloty`. The
SwiftPM URL changed:

```swift
// Old (CoatySwift 2.4.0)
.package(url: "https://github.com/coatyio/coaty-swift", from: "2.4.0")

// New (Axoloty 0.2)
.package(url: "https://github.com/phynics/axoloty", from: "0.2.0")
```

The package name is `Axoloty`. The library product is `Axoloty`. The module
is `Axoloty`. The wire-only product is `AxolotyWire` (from the `AxolotyWire`
package), module `AxolotyWire`.

## Swift version requirements

Axoloty requires Swift 6.3 (Swift 6 language mode). CoatySwift 2.4.0
targeted Swift 5.x. The minimum deployment targets are now:

- macOS 26.0+
- iOS 26.0+
- Linux (containerized)

## SwiftPM-only distribution

CocoaPods support has been removed. Axoloty is SPM-only.

## RxSwift removal

RxSwift has been removed entirely. The reactive API is replaced by Swift
structured concurrency (`AsyncStream`). All `observe*Stream()` methods now
return `AsyncStream<T>` instead of `Observable<T>`.

```swift
// Old (CoatySwift)
let disposable = manager.observeAdvertiseStream(for: Identity.objectType)
    .subscribe(onNext: { snapshot in ... })

// New (Axoloty)
let stream = try await manager.observeAdvertiseStream(withObjectType: Identity.objectType)
for await snapshot in stream {
    // ...
}
```

## mqtt-nio transport

CocoaMQTT has been replaced by [mqtt-nio](https://github.com/swift-server-community/mqtt-nio).
The `MQTTNIOClient` uses `NIOTSEventLoopGroup` (Network.framework) on Apple
platforms and `MultiThreadedEventLoopGroup` + NIOSSL on Linux.

Configuration options for broker connection remain compatible. The
`shouldTryMDNSDiscovery` option is Apple-only and explicitly errors on Linux.

## swift-log

XCGLogger has been replaced by [swift-log](https://github.com/apple/swift-log).
Use `LogManager.logger(.subsystem)` to obtain a `Logger`. The logging level
is controlled via `LogManager.setLevel(_:for:)`.

```swift
// Old (CoatySwift)
import XCGLogger
let log = XCGLogger.default

// New (Axoloty)
import Axoloty
let log = LogManager.logger(.communication)
```

## ErrorKit and AxolotyError

Errors now conform to ErrorKit's `Throwable` protocol. The package error
type is `AxolotyError` with structured cases:

- `.invalidArgument(argument:reason:)`
- `.decodingFailure(type:reason:payload:)`
- `.invalidConfiguration(option:reason:)`
- `.runtime(code:reason:)` — `RuntimeErrorCode` is an additive-only enum
- `.network(error:reason:)`
- `.caught(Error)` — wraps foreign errors at API boundaries

Never let a bare `Error` cross an Axoloty API boundary. Use
`AxolotyError.caught(_:)` or `Catching.catch { ... }`.

## Borrowed wire values

`AxolotyWire` introduces borrowed, zero-copy types (`BorrowedMessage`,
`ByteSlice`, `TopicView`) that are valid only for the duration of their
callback. Rules:

1. Never retain borrowed views.
2. Never cross async seams.
3. Validate before use.
4. Copy before returning.

See [API.md](API.md) for the full borrowed-value lifetime rules.

## Communication serialization cutover

MQTT communication events are decoded and encoded by `AxolotyWire`. The host
copies a decoded `OwnedWireEvent` before asynchronous delivery and hydrates
registered `CoatyObject` subclasses through a host-only adapter. Unregistered
object types still fall back to their declared core class and preserve custom
fields.

`CommunicationEvent.json` has been removed. Applications that need to inspect
transport bytes should use `observeRawMQTTMessageStream`; applications that
publish events should continue to use `CommunicationManager.publish*`, which
now emits AxolotyWire-owned envelopes. Configuration and persistence models
remain Codable and are unaffected.

## Linux container workflow

Axoloty builds and tests in a pinned Podman/Docker container on Linux.
The `make check` command extracts a static `axoloty-tool` binary from the
container image and runs it on the host; product commands execute inside
the container. macOS runs the same plan natively.

## Known API renames

- `CommunicationManager` methods that returned `Observable` now return
  `AsyncStream` and are `async` or `async throws`.
- `Container.resolve(components:configuration:)` and `CommunicationManager.start()`
  are now `throws` (synchronous); `Container.startAndWaitUntilReady()` is
  `async throws` and waits for broker connection and subscription readiness.
  Synchronous start and asynchronous readiness waiting are separate APIs.
- The `publishDiscover`, `publishQuery`, `publishUpdate`, and `publishCall`
  methods now return `AsyncStream<ResponseEventSnapshot>` instead of taking
  a completion handler.
- `observeAdvertiseStream` has three overloads: by core type
  (`withCoreType:`), by object type (`withObjectType:`), and namespace-wide
  (no argument) for inspecting all advertised objects regardless of type. The
  legacy `for:` argument label is obsolete.
- `axoloty-inspect` CLI provides passive catalogue and active discovery
  against a live broker without writing a custom agent. See
  [inspector.md](inspector.md).
